OBS 直播推流与本地录像配置

本页把「1帧6秒」理念落到 OBS Studio 的两大场景：直播推流与本地录像。重点只覆盖「PPT+口播 / 屏幕共享」式的讲解类直播与录屏——这正是 1f6s 倡议认定的适用内容。

使用方法

先用下方「适用性判断」确认你的内容类型属于讲解类；再按需求二选一：实时开播看推流配置，留存录制看本地录像配置。两者参数截然不同，请勿混用。

适用性判断：你的直播/录屏属于哪类？

1f6s 的本质是「用时间换空间」，只适用于信息密度低、画面变化慢的内容。开播或录像前，先用反向判断法快速分流：

你的内容特征类型本页是否适用该怎么做
PPT 讲解、桌面操作演示、屏幕共享讲座、代码走读——画面以静态/翻页为主，核心信息靠讲 讲解类 适用 继续往下看本页
实时弹幕互动、主播表情特写、现场实物演示、手势/肢体语言丰富的直播 互动演示类 不适用 用 OBS 常规高帧率推流，1f6s 会毁掉画面连续性，详见 禁用红线
红线提示

如果你的直播含实时演示动作、主播面部表情、弹幕回复时的肢体语言，画面连续性本身是内容价值的一部分。强行抽帧到 1帧/6秒 会让直播变成"PPT 翻页机"，请放弃本规范，使用 OBS 默认的 30fps 推流即可。

一、直播推流配置

推流是实时的，受上行带宽限制，且直播平台会对推流二次转码。这里有一个关键认知：推流不能直接套 1帧6秒 抽帧。

核心原则：推流用常规低码率，极致压缩留给录像后转码

直播协议（RTMP/SRT/WebRTC）要求关键帧间隔与帧率匹配平台规范。若把帧率压到 1帧/6秒、关键帧间隔设为 6 秒，观众端会严重卡顿、花屏，甚至被平台拒绝推流。正确做法是：推流时用 OBS 常规的低码率设置（讲解类 600~1200kbps 足够清晰），把 1f6s 的极致压缩留给「录像后转码」或「本地录像直接低码率」（见第二节）。

场景特征

  • 实时传输，受上行带宽限制（家用宽带上行往往只有下行的 1/5~1/10）
  • 直播平台（B站/抖音/YouTube）会对推流二次转码，源头太低质量会被进一步放大劣化
  • 讲解类画面变化慢，天然适合低码率，但不适合低帧率（直播要求连续帧）

GUI 步骤（OBS Studio，设置 → 输出）

以下按 OBS「设置 → 输出 → 输出模式：高级」路径填写。讲解类直播推荐参数：

设置项推荐值说明
输出模式高级展开全部参数控制
编码器（视频）x264（无独显）/ NVIDIA NVENC H.264（有 N 卡）有独显优先 NVENC，省 CPU；无独显用 x264（软件编码）
码率控制CBR直播必须用 CBR（恒定码率），平台按稳定码率调度，VBR 易触发卡顿

设置 → 流（推流服务与推流码）

  • 服务：选择对应平台（B站/抖音/YouTube 等）或「自定义」
  • 服务器：填平台提供的推流地址（如 rtmp://live-push.example.com/app）
  • 串流密钥：填平台直播间给出的推流码（切勿泄露）
高级参数（x264 调优、码率换算、为何推流不抽帧）

x264 高级选项（设置 → 输出 → 推流 → 高级设置）

在「x264 设置」框可粘贴以下参数（讲解类直播调优）：

x264 选项串
keyint=60:min-keyint=60:scenecut=0:tune=zerolatency:profile=main
  • keyint=60:min-keyint=60：30fps 下 2 秒 = 60 帧，与关键帧间隔 2 秒对齐；scenecut=0 关闭场景切换自适应插关键帧，保证关键帧严格等距
  • tune=zerolatency：直播低延迟调优（注意：这与录像用的 tune=stillimage 不同——直播优先延迟，录像优先画质）
  • profile=main：兼容性最佳，避免 baseline 画质不足或 high 在旧设备解码吃力
  • NVENC 用户：在「编码器」选 NVENC 后，下方有独立的「预设」「率控」「关键帧间隔」选项，无需粘贴 x264 串

码率与上行带宽换算

推流码率 + 音频码率 + 协议开销 ≈ 实际上行占用。经验：留出 30% 余量给网络波动。

  • 设 1200kbps 视频 + 96kbps 音频 ≈ 1.3Mbps；建议上行带宽 ≥ 1.7Mbps
  • 设 600kbps 视频 + 96kbps 音频 ≈ 0.7Mbps；建议上行带宽 ≥ 0.9Mbps（4G 热点也能推）
  • 测上行：speedtest.net 看上传速度，1MB/s = 8Mbps，足够推 1200kbps

为什么推流不能抽帧（技术解释）

直播平台的转码服务器假设推流是连续帧率（通常 30/60fps）。它按固定关键帧间隔（多要求 2 秒）切片 HLS 分段，再生成多档码率。若你推 1帧/6秒：

  • 关键帧间隔 6 秒 → 平台切片器按 2 秒切时会大量命中 P 帧，导致分段花屏
  • 帧率 0.17fps → 观众端播放器按 30fps 解码，每帧重复显示 180 次，但缓冲区可能因帧间隔过长判定为断流而重连
  • 部分平台直接拒绝帧率 < 10fps 的推流

结论：推流端保持 30fps + 关键帧 2 秒 + 低码率，把极致压缩交给录像后处理。

二、本地录像配置

录像没有实时带宽压力，可以离线转码——1f6s 的极致压缩正是在这里直接可用。有两条路径，按你的工作流选择：

路径对比

路径做法优点缺点
路径 A（推荐）
录高画质源 → 再用 1f6s 转码		 OBS 录制高码率源片，录完用 ffmpeg/skill 按 L4 等级别转码 源片可复用（剪辑/重压/存档）；转码参数可控；与倡议口径完全一致；支持 2-Pass 锁体积 多一步转码，需额外磁盘空间暂存源片
路径 B
OBS 录像直接套低码率		 OBS 输出→录像分栏直接设低码率/降分辨率，边录边压 省一步，录完即得压缩版 参数不如 ffmpeg 灵活；无法 2-Pass 锁体积；录砸了无源片可挽回

路径 A：录制高画质源片（OBS 设置）

目标：录一份高质量源片，供后续 1f6s 转码。设置 → 输出 → 输出模式：高级 → 录像分栏：

设置项推荐值说明
录像格式MKV容错好（录制中断不丢整文件）；录后可在「设置→高级→录像」勾选「自动重封装为 MP4」
视频编码器x264 或 NVENC H.264源片用 H.264，确保后续 ffmpeg 转码顺畅
码率控制CRF（推荐 CRF 18~23）或 VBR源片要「近似无损」留余量，CRF 18 几乎无损、23 视觉无损；若用 CBR 设 2500~4000kbps
码率（若 CBR）2500 ~ 4000 kbps给转码留足源质量；讲解类 4000kbps 已非常清晰
关键帧间隔2 秒保持默认，便于后续剪辑
预设（x264）medium 或 slow录像非实时，可用慢预设换画质
分辨率原始分辨率（如 1920×1080）源片保留全分辨率，转码时再缩到 480p/360p

音频码率128 ~ 160 kbps / 48kHz源片音频留余量，转码时再压到 20k/8k

录完后，用 1f6s 转码（见录像后转码指引）。

路径 B：OBS 录像直接低码率（边录边压）

目标：边录边压，录完即得 1f6s 风格的压缩版。设置 → 输出 → 输出模式：高级 → 录像分栏：

设置项推荐值说明
录像格式MP4 或 MKV直接交付选 MP4；怕录制中断选 MKV（再重封装）
视频编码器x264便于直接套 tune=stillimage
码率控制CRF 34对齐 1f6s L4/L5 的 CRF 值；或用 CBR 300~500kbps（讲解类极低码率）
码率（若 CBR）300 ~ 500 kbps讲解类 480p 黑白下 300kbps 文字仍可辨
关键帧间隔2 秒保持默认
预设（x264）medium平衡画质与编码负载
分辨率（缩放分辨率）854×480（480p）对齐 1f6s L1~L5 分辨率；极低带宽可降到 640×360（360p）
帧率30 FPSOBS 无法在录像时直接抽帧到 1帧/6秒（那是 ffmpeg 后处理），保持 30fps，靠 CRF/码率+分辨率降体积
音频码率48 ~ 96 kbps / 48kHzOBS 不便设 8kHz，用 48kbps 兜底；极致压缩交给后处理
路径 B 的局限

OBS 录像无法在录制时实现 1帧/6秒 抽帧（fps=1/6 是 ffmpeg 滤镜，OBS 无对应选项），也无法做 2-Pass 锁定体积。因此路径 B 只能在「码率/分辨率/CRF」层面靠拢 1f6s，真正的极致压缩仍需路径 A 的录后转码。若你追求倡议完整参数（抽帧 + 8k 音频 + 2-Pass），请走路径 A。

高级参数（自定义 FFmpeg 输出、MKV 重封装、灰度滤镜）

OBS 自定义 FFmpeg 输出（设置 → 输出 → 输出模式：高级 → 录像格式选「自定义 FFmpeg 输出」）

若想边录边套 tune=stillimage 或灰度滤镜，可在「自定义 FFmpeg 输出」里配置：

  • 视频编码器：libx264
  • 视频参数（FFmpeg 参数框）：-preset slow -tune stillimage -crf 34 -pix_fmt yuv420p
  • 视频滤镜（可选，转黑白）：format=gray（讲解类内容可加，进一步降体积）
  • 音频编码器：aac，参数：-ac 1 -ar 22050 -b:a 20k（对齐 L4 音频）

注意：OBS 自定义 FFmpeg 输出仍无法设 fps=1/6 抽帧（录制源是实时流），抽帧只能后处理。

MKV 录制后重封装为 MP4

路径 A 用 MKV 录制更安全，交付前可无损重封装（不重编码，秒级完成）：

bash · ffmpeg 无损重封装
ffmpeg -i recording.mkv -c copy -movflags +faststart recording.mp4

灰度滤镜（路径 B 进阶）

若用 OBS 普通录像模式（非自定义 FFmpeg），可在「来源」的视频采集/窗口采集上右键→滤镜→添加「视频处理滤镜」→选「灰度」实现黑白，等效 format=gray。

录像后转码指引（1f6s 落地）

路径 A 录完源片后，用 1f6s 工具转码即可得到倡议标准输出。两种方式：

方式一：用 1f6s 脚本（推荐）

仓库自带 skill/1f6s-compress/1f6s.sh，一行命令完成探测+转码：

bash · 默认 L4 压缩
# 默认用 L4(1帧/6秒 + 480p 黑白 + CRF34 + stillimage)压缩
./skill/1f6s-compress/1f6s.sh recording.mp4

# 指定级别
./skill/1f6s-compress/1f6s.sh recording.mp4 L4 -y

# L7 锁定目标体积(如 8MB)
./skill/1f6s-compress/1f6s.sh recording.mp4 L7 --target 8 -y

产物默认 recording_1f6s.mp4，不覆盖源片。详见 1f6s 工具 README。

方式二：直接用 ffmpeg 命令

对应 八级规范 的完整命令，最常用的 L4：

bash · ffmpeg L4
ffmpeg -i recording.mp4 -vf "fps=1/6,scale=-2:480,format=gray" -c:v libx264 -preset slow -tune stillimage -crf 34 -c:a aac -ac 1 -ar 22050 -b:a 20k -pix_fmt yuv420p recording_1f6s.mp4
推荐工作流

直播推流（低码率 1200kbps）的同时开启本地录像（路径 A，CRF 18 高画质源）——一次直播同时产出：① 实时观众看的推流；② 录完的源片；③ 源片用 1f6s 转码后的归档/分发版。三者参数互不干扰，是讲解类直播的最优工作流。

常见问题

推流为什么不能直接抽帧到 1帧/6秒？

直播协议（RTMP/SRT）和平台转码器假设推流是连续帧率（30/60fps），按固定关键帧间隔（通常 2 秒）切片。1帧/6秒 会导致切片器大量命中非关键帧而花屏，播放器缓冲区也可能因帧间隔过长判定断流重连，部分平台甚至直接拒绝帧率过低的推流。推流保持 30fps，抽帧交给录像后处理。

关键帧间隔为什么是 2 秒而不是 6 秒？

2 秒是直播平台的通用要求（B站、抖音、YouTube 均如此），平台按此切片 HLS 分段。6 秒的关键帧间隔会让分段过长，观众首帧延迟增大、seek 不灵敏。1f6s 的「6 秒」是抽帧间隔（画面更新频率），与直播的关键帧间隔是两个不同概念，不可混用。

录像用 MKV 还是 MP4？

录制中优先 MKV——若 OBS 崩溃或断电，MKV 文件仍可恢复；MP4 在未正常关闭时会损坏整文件。OBS 支持录完后自动重封装为 MP4（设置→高级→录像→勾选「自动重封装」，格式选 MP4）。交付分发时用 MP4（兼容性最佳）。

用 NVENC 还是 x264？

有 NVIDIA 独显用 NVENC（硬件编码），省 CPU、直播时游戏/软件更流畅；无独显或追求极致画质用 x264（软件编码），同码率下 x264 画质略优。讲解类直播两者差异不大，优先选能减轻系统负担的。注意：1f6s 转码用 ffmpeg 时统一用 libx264，与 OBS 选什么无关。

录完的源片还需要再压吗？

看用途。归档/分发/发送 → 用 1f6s 转 L4/L7 压到 16~19MB/8MB；后续剪辑 → 保留源片不动；上传平台 → 用 L1 彩色版（平台会二次转码，源头别太差）。源片建议保留一份在冷存储，日常分发用压缩版。

总结

讲解类直播与录屏的 OBS 配置，核心在于分清实时与离线的边界：推流追求稳定连续（30fps + 低码率 + 关键帧 2 秒），极致压缩交给录像后转码（1f6s 抽帧 + 灰度 + stillimage）。两者参数互不干扰，一次直播可同时产出推流与可归档源片。

核心原则

推流不抽帧，录像留源片，转码用 1f6s——实时保连续，离线保极致。
