PPT 生成 Skill

把主题或大纲从零生成，或把给定的网页 PPT 转换成符合「1帧6秒」PPT 抗压缩规范的 HTML 幻灯片 deck。产物是自包含的单个 .html 文件——内联 CSS + 极简翻页 JS，零外部依赖，浏览器双击即可键盘翻页 / 全屏演示。

这是什么

一个可分享、供任意 agent 读取照做的 playbook（skill/SKILL.md）。agent 读到它后，按给定的主题或页面，直接产出一套逐页落实抗压缩规范的幻灯片。它服务于倡议的核心主张——演示文稿必须从源头适配极限压缩。

两种工作模式

模式触发输入产物
生成模式（重点） 用户给主题或大纲 主题 / 大纲要点 从零生成符合规范的 deck
转换模式 用户给一个网页 PPT 文件路径（HTML） 任意 HTML 幻灯片/页面文件路径（如 my-deck.html、slides/intro.html，也可以是本站页面如 levels.html） 把该网页 PPT 内容转成符合规范的 deck

默认约定：合并成单文件 deck；输出落盘到仓库 slides/ 目录，文件名形如 slides/<主题或页面名>-deck.html。

抗压缩规范摘要

生成的每一页都必须严格遵循 design.html 中的「PPT 抗压缩设计规范」。要点：

  • 仅三色：纯黑 #000000、中度灰 #808080、纯白 #FFFFFF——杜绝任何彩色
  • 无衬线字体：思源黑体 / 微软雅黑 / Arial；严禁宋体、楷体等衬线字体
  • 最小字号：正文 ≥ 24pt，标题建议 ≥ 36pt，中度灰文字 ≥ 28pt
  • 线条 ≥ 3px：边框、表格线、图表线一律 ≥ 3px，细线在 360p 会断裂
  • 纯色背景：纯白或纯黑；严禁渐变、纹理、图片水印
  • 零阴影零渐变：禁用 box-shadow / text-shadow / gradient / 三维效果
  • 图表不靠彩色区分：纯黑实心 + 纯白描边 + 斜线/点阵图案填充交替
铁律

结构可借、样式必须新建。可复用源页的 HTML 语义结构，但严禁直接引用 assets/css/style.css 或 assets/js/main.js——它们含彩色、阴影、渐变、小字、细线，全面违反本规范。幻灯片必须使用 skill 内嵌的独立样式表。

调用约定与示例

调用本 Skill 时，arguments 按下列格式传：

生成模式

调用示例
# 只给主题,由 skill 规划大纲
run_skill ppt "主题: 团队周报规范"

# 给定大纲,按大纲逐页生成
run_skill ppt "主题: 团队周报规范; 大纲: 本周进展, 风险与阻塞, 下周计划, 数据看板"

# 可选附加约束
run_skill ppt "主题: 团队周报规范; 受众: 全员; 页数: 约8页"

产物：slides/团队周报规范-deck.html

转换模式

调用示例
# 转换一个给定的网页 PPT
run_skill ppt "转换: my-deck.html"
# 产物: slides/my-deck-deck.html

# 转换本站页面作为示例(本站页面也是合法的网页 PPT 输入)
run_skill ppt "转换: levels.html"
# 产物: slides/levels-deck.html

工作流要点

生成模式 5 步

  1. 拆解输入：提炼主题、受众、要点；只给主题时规划 5~12 个要点（一要点 ≈ 一页）
  2. 规划页面序列：封面 → 目录 → 内容页（一页一要点）→ 末页致谢；宁可多拆一页，不要挤一页
  3. 逐页生成：每页选页型（封面/目录/要点/表格/图表/对比/代码/清单/致谢），套用最小合规片段，逐条落实强制动作（字号档位/三色化/线条加粗/禁用效果/图表合规/背景纯色/无外部依赖）
  4. 自检：对信息最密的一页跑「三步自检法」（缩小测试/去色测试/细线扫描）
  5. 落盘：输出到 slides/<主题>-deck.html

转换模式切片规则

  • 一级切片：源网页 PPT 的 <section id="…"> 为单位，一个 section → 一张幻灯片
  • 二级切片（内容过密时下钻）：如某页面含 L1~L8 八级则各一张、含 9 个场景则各一张
  • 剥离：去掉 header 导航、footer、页间 hr/nav（幻灯片用键盘翻页取代）
  • 样式重做：表格去 shadow、表头改黑白、徽章去彩色改文字、callout 去彩色边、代码块改深底白字

自测样本

样本 A — 生成模式

对 design.html 的「PPT 抗压缩设计规范」内容，用生成模式产出 deck。输入理解为：主题: PPT抗压缩设计规范; 大纲: 字体字号, 色彩灰度, 版式留白, 特殊元素, 三步自检。预期产物 slides/design-deck.html，约 7 张。核验：纯黑白灰、无阴影渐变、字号 ≥24pt、线条 ≥3px、键盘可翻页、可全屏。

样本 B — 转换模式

以本站 levels.html 作为给定的网页 PPT 示例，用转换模式产出 deck。输入：转换: levels.html。预期产物 slides/levels-deck.html，约 10~11 张。核验：L1~L8 各一张、表格去 shadow 表头改黑白、徽章去彩色改文字、ffmpeg 命令在深底代码页、剥离 header/footer。换成任意其它网页 PPT 文件同理。

常见问题

这个 skill 和 design.html 是什么关系？

design.html 是规范本身——告诉人"该怎么做"；本 skill 是规范的可执行落地——让 agent "直接做出来"。规范是约束，skill 是执行。遵循本 skill 产出的幻灯片，在 L4/L5 级别（CRF 34 + stillimage）下清晰度等同普通文稿在 CRF 28 下的效果，体积再降约 40%。

生成的幻灯片能用彩色吗？

不能。抗压缩规范强制仅三色（纯黑/中度灰/纯白），杜绝任何彩色。需要表达"区分"时，用斜体/下划线/图案填充，而非依赖灰度深浅或彩色。这是为了让幻灯片在被压缩成黑白低分辨率视频后依然可读。

能加动画 / 过渡效果吗？

不能。幻灯片是静态的，靠键盘翻页（←/→/Space/Home/End/F 全屏）。动画和过渡在压缩后要么丢失要么变成模糊残留，且增加编码负担。画面越简单，编码器越省力，压缩后越清晰。

产物文件在哪？

默认输出到仓库 slides/ 目录，文件名 <主题或页面名>-deck.html，小写、空格用连字符。单文件 deck（内联 CSS + JS），可直接双击在浏览器打开。

agent 没有 run_skill 怎么用？

本 skill 的 skill/SKILL.md 是一份纯 Markdown playbook，任意 agent 读取后即可照做——它不需要特定框架。agent 按其中的页型清单、模板与强制约束，直接生成符合规范的 HTML 即可。

获取方式

本 Skill 是一个纯 Markdown playbook，无运行时依赖，拿到即可用。

方式做法
克隆仓库 git clone https://github.com/brnme/1f6s.git，文件位于 skill/SKILL.md
直接下载 GitHub 上打开 skill/SKILL.md，点 Raw → 另存为
喂给 agent 把 skill/SKILL.md 内容粘贴进任意 agent 的对话/系统提示，agent 读后即可按其中页型清单与模板生成 deck
文件位置

仓库 skill/SKILL.md（单文件）。无需安装、无需额外依赖——它是一份 playbook，agent 读懂就能照做。

总结

PPT 生成 Skill 让「源头适配极限压缩」从口号变成可复现的产出：给主题或页面，得到一套纯黑白灰、大字粗线、零阴影零渐变、自包含可演示的幻灯片。它与 视频压缩 Skill 互补——前者让源头幻灯片扛得住压缩，后者把成品视频压到规范体积，共同构成从源头到成片的完整闭环。

核心原则

画面越简单，编码器越省力，压缩后越清晰——这是抗压缩设计的延伸，也是 1帧6秒 的源头抓手。
